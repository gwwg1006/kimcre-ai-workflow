# 데모 시나리오

가상 고객 "홍길동"의 문의 한 건이 접수부터 배송 완료까지 흐르는 과정입니다. 모든 데이터는 `data/examples/`의 가상 데이터입니다.

```bash
cd backend
python3 -m app.demo --today 2026-11-02
```

실제 출력 (타임스탬프만 고정값으로 바꿨습니다):

```text

=== 1. 문의 입력 (원문, 로컬에만 존재) ===
안녕하세요, 저는 홍길동입니다.
전자기기 케이스 시제품을 PLA 검정색으로 4개 출력하고 싶습니다. 후가공은 필요 없고, 2026-11-15까지 받고 싶어요.
배송지: 서울 마포구 월드컵북로 123 4층 / 연락처 010-1234-5678 / 메일 gildong@example.com


=== 2. 로컬: 개인정보 분리 ===
안녕하세요, 저는 [NAME]입니다.
전자기기 케이스 시제품을 PLA 검정색으로 4개 출력하고 싶습니다. 후가공은 필요 없고, 2026-11-15까지 받고 싶어요.
배송지: [ADDRESS] 4층 / 연락처 [PHONE] / 메일 [EMAIL]

분리된 항목(로컬 보관): {'EMAIL': 1, 'PHONE': 1, 'ADDRESS': 1, 'NAME': 1}

=== 3. 로컬: 제작 요구사항 추출 (비식별 텍스트만 입력) ===
엔진: rules
OrderRequirements(material='PLA', quantity=4, color='black', post_processing='none', deadline='2026-11-15', description='전자기기 케이스 시제품', weight_g_per_unit=60.0, print_hours_per_unit=3.0)

=== 4. 접수 확인 / 추가 정보 요청 ===

[접수 확인] (문장 다듬기: mock)
홍길동님, 문의가 접수되었습니다. 제작 조건을 확인해 견적을 보내드리겠습니다. (접수번호 ORD-DEMO-001)

=== 5. 견적 생성 + 고객 응답문 ===
합계 35,900원 / 납기 2026-11-05 / 가정: ['개당 60g / 3h 추정 (슬라이서 결과로 대체 가능)']

[견적 전달] (문장 다듬기: mock)
홍길동님, 견적 초안입니다.
- 소재비 (PLA 60g x 4): 8,400원
- 장비 사용료 (12h): 24,000원
- 배송비: 3,500원
합계 35,900원 / 예상 완료 2026-11-05 (희망 납기 충족)
진행을 원하시면 승인 답장을 부탁드립니다.

=== 6. 승인 -> 제작 -> 배송 (주문 상태 변경) ===

[제작 승인 확인] (문장 다듬기: mock)
홍길동님, 제작 승인이 확인되었습니다. 결제 확인 후 제작 일정을 확정해 안내드리겠습니다. (접수번호 ORD-DEMO-001)

[제작 시작] (문장 다듬기: mock)
홍길동님, 제작을 시작했습니다. 예상 완료일은 2026-11-05입니다. (접수번호 ORD-DEMO-001)

[발송 안내] (문장 다듬기: mock)
홍길동님, 제작이 끝나 발송했습니다. 운송장 MOCK46F6DC47AD로 배송 조회가 가능합니다.

[배송 완료 안내] (문장 다듬기: mock)
홍길동님, 배송이 완료되었습니다. 받아보신 결과물에 문제가 있으면 언제든 연락 주세요.

=== 7. 주문 상태 이력 ===
2026-11-02T09:00:00  접수
2026-11-02T09:00:00  견적 전달
2026-11-02T09:00:00  제작 승인
2026-11-02T09:00:00  제작 중
2026-11-02T09:00:00  배송 중
2026-11-02T09:00:00  배송 완료
```

## 발표 때 보여줄 포인트

1. 2단계: 이름·전화·메일·주소가 `[NAME]` 등으로 바뀌는 순간 (개인정보 분리)
2. 3단계: 가려진 텍스트만으로 제작 조건이 구조화되는 것
3. 5단계: 규칙 기반 견적과 납기 충족 여부 판단
4. 6단계: 외부 LLM으로는 `[NAME]`이 가려진 문장만 나가고, 이름은 로컬에서 다시 채워진다는 점 (`OPENAI_API_KEY`를 넣으면 이 구간에서 실제 호출)
